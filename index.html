Live tool 1 — try it now

Inbox Triage

Paste a batch of inbound messages — support tickets, contact-form leads, whatever lands in a shared inbox — and get each one categorized, scored for urgency, and given a drafted reply. The kind of manual first-pass sorting that eats an hour a day in a lot of small businesses.

Claude Haiku 4.5 Forced tool use No server, no data stored

Results will appear here.

How this works, and why

The messages go to Claude with a forced tool call (tool_choice: {type: "tool", name: "submit_triage"}) against a strict: true JSON schema, instead of a prompt asking for "JSON only, no markdown" and hoping the reply parses. The API guarantees the response matches the schema — urgency is an integer, sentiment is one of four fixed values, nothing is missing — so there's no markdown-fence-stripping or try/catch-and-pray around JSON.parse. This is the same "function calling" mechanism real AI agents use to take reliable action, not a chatbot trick.

Live tool 2 — try it now

Content Repurposer

Paste a long-form article or transcript and get it back as a LinkedIn post, an X/Twitter thread, and a newsletter blurb — three drafts, matched in tone to the original, ready to edit and post.

Claude Sonnet 5 Forced tool use No server, no data stored

Results will appear here.

How this works, and why

Same forced-tool-call pattern as Inbox Triage, different schema — submit_repurposed_content requires exactly a linkedin_post string, a twitter_thread array of strings, and a newsletter_blurb string, so the UI can render all three the moment the response arrives instead of guessing at a text response's structure. This one runs on Sonnet 5 rather than Haiku: matching tone across three formats is a harder writing task than classification, and it's worth the extra cost for that reason specifically — not by default.

How I work

I design what needs to be built, direct AI to build it, and treat the output the way you'd treat a junior engineer's pull request — read it, test it, and fix what's wrong before it ships. The front-end projects below document that loop honestly: several had real gaps (a missing shader, a missing stylesheet, missing assets) and real bugs (mobile overflow, z-index conflicts, a performance bug in a 3D scene) that I found and fixed, not glossed over.

That's the same skill the automations above are built on: knowing what a workflow actually needs, getting AI to do the repetitive part correctly, and verifying it before it touches a real inbox, a real form, or a real customer.
